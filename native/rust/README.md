# 天气首页顶栏模糊

在 MeowCeiler 首页进入「天气」，开启「首页顶栏模糊」。天气首页滚动时，顶栏下方的内容会模糊显示。选择「应用并重启天气」可立即重新打开天气，选择「下次冷启动生效」则等待天气进程下次启动。关闭后同样在冷启动时恢复。

## 兼容范围

已确认的组合是 marble、天气 18.0.0.27-R、主用户的独占应用 UID。需要 root、ZygiskNext API 4 / HyOS API 1，以及已启用且支持载荷交付的 NativeRelay。已核对的模块是 `0.6.0-payload-probe`（versionCode 9）。安装器仅检查框架目录及启用状态，运行时再检查 HyOS 接口。后续模块和天气版本需分别验证。

本次核对的模块文件为 `native-relay-hyos-payload-probe-0.6.0.zip`，SHA-256 为 `ae2d7766f7d52324dc22103ba8ad0eb592b9fc2af5e46b448d22fbcbca0bd704`。现有无版本号的 `native-relay-hyos-probe.zip` 为 0.1.0，`native-relay-hyos-entry-probe.zip` 为 0.2.0，两者均低于天气功能所需版本。

## 配置和状态

天气页提供一个开关。旧偏好和备份中同时开启天气总开关、将背景模糊支持设为强制开启的用户会保留开启状态。其余旧配置迁移为关闭。保存设置失败时，界面保留待应用状态。

`weather-config` 使用 schema 3，编码为两字节 `[3, enabled]`，其中 enabled 取 0 或 1。读取旧配置时校验原字段的范围，并按上述规则解码。载荷 ABI 版本和业务配置 schema 独立演进。

「天气已接收设置」表示本次启动的天气进程已回报初始化成功。实际效果需在天气首页滚动时观察。模块总开关关闭后停止后续交付，先前启动的天气进程在退出时释放已加载的载荷。

## 组件与生命周期

| 组件 | 职责 |
| --- | --- |
| APK bridge | 从设置页接收开关及重启选择，在后台请求 root 服务保存配置、查询状态。 |
| `runtime` | 保存配置和版本，管理提供端，在用户选择立即应用时重启天气。 |
| `provider` 与 `service` | 核对目标身份，准备只读载荷，交付配置快照，核对回执的票据和版本。 |
| NativeRelay | 提供加载与宿主接口，天气规则、配置和业务载荷归 MeowCeiler 管理。 |
| `payload` | 在已核对的天气版本上处理首页顶栏模糊。映像或代码特征不匹配时拒绝修改。 |
| `relay-sdk` | 随项目提供带文件校验和的协议与 ABI 源码快照。 |

配置以进程为单位生效。提供端异常退出时，由监督进程按 1、2、4、8、16、30 秒退避重新启动 worker。服务空闲时阻塞等待请求。监督进程本身退出后，可由开机脚本或 APK 恢复。天气进程由系统正常回收。

宿主 V1 接口提供一次初始化、状态查询、日志和限定调用库的 PLT 安装。原函数发布需要匹配的 C ABI 和已确认的驻留期。宿主 V1 缺少可卸载映像的持有与多方安装同步保证。当前适配只覆盖已校验的常驻启动库。独立的 ELF 导入查找 API 保留在 `payload/src/imports.rs`，查找结果仅说明符号和槽位的对应关系。

## 构建与检查

Gradle 的 `buildNativeWeather` 任务使用 Rust 1.95.0、`aarch64-linux-android` 和 NDK 28.2.13676358，将提供端和天气载荷放入 APK 的 arm64 库目录。Rust 依赖由锁文件固定，构建从本机 Cargo 缓存读取。

在 `native/rust` 下运行 `sh scripts/verify.sh` 检查映像范围、权限、文件指纹与 ELF 导入查找。`cargo test --locked --offline -p meow-weather-config` 检查新配置往返和旧配置迁移。两组检查均使用本地数据。
