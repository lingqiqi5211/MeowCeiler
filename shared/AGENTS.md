# shared 模块规范

## 职责与依赖

- 存放 UI 与 Hook 共用的设置、设备信息、日志和安全模式协议。
- 不引入页面、Activity、宿主 Hook 注册或应用服务实现；只包含两侧都可安全使用的逻辑。
- 设备属性和静态字段读取复用 EzHookTool core；不为普通设置进程引入 Xposed 运行时调用。

## 设置契约

- `Preferences` 是键名、类型和默认值的唯一来源。默认值须能用于远程设置不可用的情况。
- 新键同步加入 `Preferences.all`，核对备份、导入、重置、UI 控件和 Hook 读取。
- 已发布键不随意改名或改类型；枚举持久化使用稳定字符串，数值设置明确单位、范围和恢复默认的语义。
- 不为 PackageManager 已持有的组件启用状态再建一份独立偏好。

## 协议与标识

- UI 与 Hook 使用相同的偏好文件名、Provider authority、方法名和字段编码。
- 修改记录编码时保持分隔符、转义、损坏记录处理及版本失效规则一致。
- 安全模式记录和解锁前系统属性镜像有不同的访问条件；明确真实来源，不让默认值覆盖尚未读取的记录。
- `Scope` 的变动同步 `app/src/main/resources/META-INF/xposed/scope.list` 和注入注册。
- 模块包名、桌面别名、设置入口常量必须与 Manifest 和 `applicationId` 一致。
- 设备检测区分「读取成功且为 false」与「读取失败」，兼容分支须有源码或设备依据。

## 验证

- 核对设置键唯一性、注册完整性、类型、默认值和两侧接线。
- 改协议时检查编码往返、缺失或损坏输入、旧数据及版本失效行为。
- 获准构建时编译依赖该契约的 UI 与 Hook，不能仅以 shared 单独编译通过作为完整验证。
