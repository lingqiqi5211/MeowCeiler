# app 模块规范

## 职责

- 管理 `SettingsActivity`、框架桥接、日志 Provider、文件分享、Manifest 和 APK 打包。
- 页面放在 `ui`，宿主修改放在 `hook`，跨进程常量放在 `shared`。

## 启动与框架连接

- 复用 MeowUI 的偏好存储和服务连接，不重复注册框架监听覆盖已有连接。
- Activity 持有的存储、监听与协程按生命周期释放。框架未连接时仍须能打开设置，并明确报告写入失败。
- 外观初始化须考虑远程偏好尚未就绪的情况；不让用户看到默认缩放后再跳到已保存值。
- 作用域申请以框架批准结果为准。热重载保留目标状态筛选和系统关键进程排除规则。
- 不在主线程执行阻塞的 Binder、文件或包管理查询。

## 组件与日志

- 隐藏桌面图标只禁用 `LauncherAlias`，不能禁用 `SettingsActivity`；保留框架可打开的设置入口。
- 修改包名或组件名时同步 `shared` 常量、Manifest、Provider authority 和相关调用。
- 日志 Provider 的导出是跨进程写入所需，必须保留调用方 UID 校验；不能信任传入包名。
- 解锁前日志使用 DE 存储。修改日志格式或压缩过程时核对两代记录、半行残留与原子替换行为。
- 文件分享使用 FileProvider 的受限路径和临时 URI 授权，不扩大导出范围。

## 打包与验证

- 签名数据留在本机配置，不输出密码、不提交签名文件；不要通过改包名或卸载旧应用绕过签名冲突。
- libxposed 宿主 API 保持编译期依赖；保留 Xposed 入口和反射依赖所需的 R8 规则。
- 改 Manifest 检查组件可达性和权限；改启动或桥接检查连接失败、重连和销毁路径。
- 获准构建时使用对应变体；获准装机时从该次构建的输出元数据定位 APK，核对安装版本和启动结果。
