# hook 模块规范

## 组织与生命周期

- 注入入口负责初始化、宿主分发和释放；宿主注册放在 `scopes`，功能放在 `rules`，通用能力放在 `base` / `util`。
- 只在某个宿主里成立的封装放 `utils/<作用域>/`，与跨宿主通用的 `util/` 分开；规则文件只留接点与样式。
- 复用 `BaseHooker` 的父子启用状态，不绕过模块总开关、安全模式或重复安装 Hook。
- `StaticHooker` 适用于需重启宿主生效的结构和样式修改；`DynamicHooker` 的回调须检查 `enabled`，不能假定关闭开关会卸载 Hook。
- 需要 Context 或 Resources 时使用既有 attach 生命周期；不在宿主 Context 尚不可用时强取。
- 热重载时关闭旧存储、协程和监听，避免跨代持有已取消的 scope 或旧类加载器。

## 适配与性能

- 优先使用 EzHookTool 的类、字段、方法和 Hook API；隐藏 API 桩仅用于可合法提供编译桩的整类。
- 目标类名、签名、资源名和版本分支以宿主源码或反编译证据为准，不添加猜测性兜底。
- 宿主资源在大版本间会换形态（同名图标可能从资源表挪进 assets），按版本各取一次证据，两条路都留。
- 类、方法、字段和资源 ID 尽量在初始化阶段解析；避免在逐帧或高频回调中重复反射、生成字体或执行 IO。
- DexKit 查询复用会话和磁盘缓存；查询语义改变时更新缓存键，并保留宿主版本、split APK 和类加载器失效处理。
- 修改 View、字体、尺寸或静态字段时保存宿主原值，关闭选项或恢复默认后能还原；注意宿主后续资源刷新。
- 不以修改系统动画掩盖无关样式问题。已有兼容分支只有在当前任务授权且有证据时调整。

## 契约、日志与安全

- 从 `shared/Preferences` 读取设置，不另写同名键或不同默认值。新增功能同步宿主注册、UI 入口和必要的日志标题映射。
- 使用 `Feature` 记录功能和已核对的宿主版本；用户文案放在 UI 资源中。
- 复用 `MLog`、异常隔离和安全模式上报；不吞掉导致功能未安装的错误，也不让异常穿透宿主回调。
- 高频诊断须受调试开关控制，不记录密钥、私密内容或无关视图数据。
- 日志投递和磁盘操作使用已有后台通道，不阻塞宿主主线程。

## 验证

- 检查首次加载、开关关闭、默认恢复、资源刷新和热重载后的生命周期。
- 获准构建时编译 Hook 及应用；获准装机时核对目标版本、作用域、日志和功能实际效果。
- 静态调用链检查不等于宿主验证；未连接的设备或未覆盖的系统版本不得记为通过。
